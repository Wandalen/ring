# id

## Representation

Private module declaration bringing `src/id.rs` into the crate root. Holds eight
items: the [`Seq`](../struct/002_seq.md) and
[`SlotIndex`](../struct/003_slot_index.md) structs, their two inherent impls
([005](../implementation/005_impl_seq.md),
[006](../implementation/006_impl_slot_index.md)), the
[`ZERO`](../associated_constant/001_seq_zero.md) constant, and four associated
functions — [`next`](../associated_function/007_seq_next.md),
[`advanced_by`](../associated_function/008_seq_advanced_by.md),
[`distance_to`](../associated_function/009_seq_distance_to.md),
[`SlotIndex::get`](../associated_function/010_slot_index_get.md).

114 lines. **The only module holding two types**, and the pairing is the point:
its module doc argues that keeping the sequence apart from the slot is what lets
a gate compare two positions a full lap apart, which is impossible once both have
been folded into `0..capacity`.

Imports nothing — not from a sibling, not from `core`. It shares that with
`policy`; `grep -n '^use \|^pub use ' src/*.rs` returns six lines, four of them
`lib.rs`'s re-exports and the other two `capacity.rs:8` and `error.rs:13`
(→ [`../../data_structure/001`](../../data_structure/001_two_position_types_and_the_fold_between_them.md)).

**The declaration order in `lib.rs` is alphabetical, not dependency order.**
`capacity` is declared first at line 36 and is the only module with a sibling
dependency; `id` sits third with none. Alphabetical ordering is harmless here
precisely because the graph is one edge deep — a crate whose modules formed a
chain would make the ordering misleading.

Test-only references: none directly — `tests/types_test.rs` reaches both types
through the crate-root re-export.

**The module with the widest reach through its contents.** `Seq` alone is named
in the `src/` of eighteen sibling crates, more than any other item in the family
— but the module itself is reachable from none of them, which is what `mod`
rather than `pub mod` buys.
