# presentation

The Ukrainian deck for the bootcamp capstone defence: a 4-minute talk over eight slides for an
audience new to lock-free queues. It runs problem → how claim, publish and drain work → why
without a lock → what the ring guarantees → the hardware tricks → the checks CI runs, and closes on
a sandbox where `ring_mpsc`, compiled to WebAssembly, runs live. The rings on the title and the
storyboard come from the same build.

Open [`index.html`](index.html) from disk. `→`/`←` move between slides, `n` shows the notes, `s`
the full speech, `t` the timer. Fonts come from Google Fonts when online; offline, system fonts
stand in.

## Engine

[`deck_engine/`](deck_engine/lib.rs) puts `ring_mpsc` behind a one-line text protocol (`reset`,
`claim`, `publish`, `push`, `drain`, `state`) that answers JSON, and builds to
`wasm32-unknown-unknown` with no imports. A claim is a held `Reserved` guard, so a producer can
take a ticket now and publish later, which is what the storyboard and the sandbox show. The deck
embeds the module as base64 and runs it in the page. It is its own workspace root, so CI and
`verb/test` never build it. The gates still see its manifest: it is declared in
`bench_harness/gate/declared/exempt.txt` and, because it names `ring_mpsc`, in
`declared/ring/internal_consumers.txt`.

Where WebAssembly is blocked, as in some sandboxed viewers, the deck falls back to
[`src/mirror.js`](src/mirror.js), a JS port of the same rules; the badge in the nav bar says which
one runs. [`mirror_test.cjs`](mirror_test.cjs) holds the port to the wasm build: random sessions
through both, failing on the first answer that differs. Last run: 3 000 sessions, 209 653
commands, none different.

## Build

```bash
rustup target add wasm32-unknown-unknown
python3 docs/presentation/build.py
node docs/presentation/mirror_test.cjs 3000
cargo test --manifest-path docs/presentation/deck_engine/Cargo.toml
```

`index.html` is generated; edit `src/` or `deck_engine/` and rebuild.

## Responsibility Table

| File | Responsibility |
|------|-----------------|
| [`index.html`](index.html) | The deck — generated by `build.py`, engine and scripts inlined |
| [`build.py`](build.py) | Builds `deck_engine/` to wasm and inlines it with `src/` into `src/deck.html` |
| [`src/deck.html`](src/deck.html) | Slides and styles, with the slots `build.py` fills |
| [`src/app.js`](src/app.js) | The ring drawing, the storyboard, the sandbox, navigation and speaker notes |
| [`src/mirror.js`](src/mirror.js) | JS port of the engine, used only when WebAssembly is unavailable |
| [`deck_engine/`](deck_engine/Cargo.toml) | `ring_mpsc` behind the text protocol, built to wasm32 |
| [`mirror_test.cjs`](mirror_test.cjs) | Random sessions through the wasm build and `src/mirror.js`; they must agree byte for byte |
