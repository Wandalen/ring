The crate is 666 lines of `src/` holding one `AtomicBool`, and the corpus above is
several times larger. The reason is that almost nothing here is a data structure:
the crate's whole content is a *claim* — that a drain cannot start on an open ring,
that a close orders teardown, that a refusal hands the record back — and a claim is
checked by reading it against the code rather than by running it. That is also where
the findings come from. The recurring shape across all thirteen definitions is a
sentence stated more strongly than the code supports: a doc comment promising a token
is unique when the constructor takes `&self`, a surface column grading a guarantee an
accessor reaches past, a dependency list one entry short of its own manifest.

Indexed here and in [`decisions/readme.md`](../decisions/readme.md) only, not in
`graph.yml` — `doc_des.rulebook.md` classifies `docs/decisions/` as a
non-doc-definition directory. Both are open, and both ask the same question from
opposite ends: what a caller can still reach after the type system was supposed to
have stopped them. `001` is about the documented exit, `002` about the undocumented
supply, and neither is answerable from this crate's own callers, because it has
almost none — one crate binds a `Stopped`, and nothing outside holds a `Guarded`.

### Why `decisions/` Has Instances Here and Not in `ring_core`

`ring_core`'s three design choices were each settled, so each is documented where it
takes effect rather than filed as a live decision. This crate has two that genuinely
are not, and both are undecidable on its own evidence for the same reason: the caller
population that would settle them does not exist yet. Each is filed with the
measurement that would settle it and the stage that owns it — and
SD13 records that one of those two measurements, as written, cannot report the
threshold it routes on.

### What This Index Used to Exclude

Until the corpus standard fixed the definition set at thirteen, this page carried a
section arguing that four definitions did not belong here. Three of those arguments
have since been overtaken and their directories exist:
`data_structure/` (SD9–SD12), `non_functional_requirement/`
(SD33–SD36) and `item/` (SD25–SD28). The fourth still holds —
there is no `format/`, because nothing here is a byte layout another program must
agree on.

The overtaken arguments were not wrong about the crate; they were arguments from
scarcity — one `AtomicBool` is not a data structure, an unmeasured cost should not be
written as a requirement, a per-item catalog would be written 33 times. What the
standard changed is that each of those directories now has to be *filled*, and filling
them is what produced twelve of the fifty-two findings below. The unmeasured cost, in
particular, is now measured and filed rather than deferred
([`non_functional_requirement/001`](../non_functional_requirement/001_what_a_guarded_push_costs.md)).
