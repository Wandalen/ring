Open questions and glossary

What the investigation did not settle, with the confidence each reading carries, and the terms the page uses.

Open questions

  1. Why is a 64-byte stride slow at the frontier? Ruled out: 4K aliasing, more line sharing, codegen. Padding to 72 bytes fixes it; the mechanism needs hardware counters.
  2. Why did #41 slow two single-thread benchmarks? Settled. The M4's whole-lap fill_drain followed the drain loop head's address mod 8 and measured equal within 0.5% with loop heads pinned; whether verb/bench should pin them is #53. The x86 runner's 22% loss on one-record drains was the compiled shape of the first version (a length LLVM could not see as constant), fixed in #41's final version; the x86 CI run confirms it or not (#50). The 16384-slot cell is #49.
  3. What holds TypedSlot at 16384 slots to 25–48 M/s in every mode and layout? Likely the 256 KB slot array spilling the 128 KB L1D (CopySlot's is exactly 128 KB). The regimes review rates the label medium and the cause low. #41 takes pop1 there from 46, 47 to 36, 35.
  4. Which mode of the bimodal popN 1024 cell is typical? The regimes review attributes the two modes to the chase's initial race (high confidence). A separate review tied the tagged flip to the slot array sitting one page after the ring, mechanism unknown.
  5. Where does the lockstep threshold sit now? The cache moved it. The steady-state model R* ≈ m / (c − p) (m one refresh ≈ 45 ns, c the consumer's cost per pop, p the producer's cost per push) was fitted qualitatively; c and p were never measured in isolation.
  6. Does the one-line layout batch about 4 records per transfer? Consistent with the timings (one-way 37.8 ns against ~9–10 ns per record), unobservable without counters. Hypothesis, ~70% confidence.
  7. Should CACHE_LINE become 128? With #41 the two layouts measure the same on pop1, so this is now a footprint decision, not a speed one.

Glossary

Cache line
The unit a cache stores, moves and keeps coherent. 128 bytes on this M4 Pro; ring_align assumes 64.
Coherence transfer
Moving a line, or its write ownership, from one core's cache to another's, invalidating the old copy. One way inside a P-core cluster: median 37.8 ns.
Stride
Bytes from the start of one slot to the start of the next: 16 for TypedSlot<u64>, 8 for CopySlot<u64>, 72 against 64 and 264 against 256 for the wide records.
Frontier
The slots the producer is writing while the consumer reads right behind it. Lines there are hot on both cores at once.
Lockstep
The full ring with the producer one slot behind the consumer: it refreshes its cached consumer cursor before nearly every push, about 48 ns each.
OWN, GATING, HANDOFF
The three orderings the ring uses. OWN is Relaxed: an end reading the cursor only it writes. GATING is Acquire: reading the other end's cursor before touching the slots it guards. HANDOFF is Release: publishing one's own cursor after the slot writes.
LDAPR, STLR
The AArch64 instructions behind them: LDAPR (and LDAPUR) an acquire load in the weaker RCpc form, STLR (and STLUR) a release store. A push does one STLR; before #41, every pop did one LDAPR.
loom
A Rust model checker. It runs a concurrent test under every interleaving the memory model permits, up to a bound, and so catches orderings a real run rarely exposes.
